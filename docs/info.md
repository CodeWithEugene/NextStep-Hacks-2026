## 3. Theme & Problem Statement: "Earth Forward"

The central track for NextStep Hacks 2026 is **Earth Forward**. Participants are tasked with identifying a pressing environmental problem affecting their community or the planet, and developing an impactful technical solution.

### Core Problem Domains & Inspiration Areas
1. **Climate Resilience & Adaptation:** Early warning systems, extreme weather tracking, flood/wildfire monitoring, urban heat island mitigation.
2. **Renewable Energy & Grid Efficiency:** Solar/wind forecasting, smart grid balancing, decentralized micro-grids, EV charging intelligence.
3. **Biodiversity & Wildlife Conservation:** Bio-acoustic tracking, camera trap ML classification, anti-poaching telemetry, invasive species identification.
4. **Ecosystem & Environmental Monitoring:** Satellite/aerial remote sensing, carbon accounting, air/water pollution sensors, deforestation detection.
5. **Sustainable Agriculture & Food Systems:** Precision irrigation, crop disease diagnostics, regenerative farming analytics, supply-chain waste reduction.
6. **Waste Reduction & Circular Economy:** Smart recycling sorting, industrial byproduct exchange, life-cycle carbon footprint calculation, food waste redistribution.

### Real-World Relevance Expectation
Organizers specifically encourage participants to ground their projects in real-world utility by designing solutions that could interface with local organizations, environmental groups, researchers, or communities rather than purely hypothetical toys.

## 5. Mandatory Submission Requirements Checklist

To be eligible for judging, every project submission **MUST** include:

- [ ] **Video Demonstration / Pitch:**
  - **Optimal Length:** **3:00 to 5:00 minutes** (Satisfies both the Rules requirement of *"3-5 minutes demoing the project"* and Overview requirement of *"no longer than 5 minutes"*).
  - Must showcase a live demo of the working product, technical architecture, and problem solved.
  - Video can be hosted on YouTube, Vimeo, Loom, or Google Drive (publicly accessible).
- [ ] **Code Repository Link:**
  - Public link to the code repository (e.g., GitHub, GitLab) for judges to inspect technical implementation.
- [ ] **Live Website or Application Link:**
  - Publicly accessible deployment URL (e.g., Vercel, Railway, Fly.io, HuggingFace Spaces) if applicable.
- [ ] **Completed Devpost Project Page:**
  - Detailed description covering inspiration, what it does, how it was built, challenges faced, accomplishments, what was learned, and what's next.
- [ ] **Pre-existing / Ongoing Projects Clause:**
  - If continuing work on a project started prior to August 21, 2026, you **MUST explicitly state in your Devpost description**:
    1. What was built **before** the hackathon.
    2. What was built **during** the hackathon.
- [ ] **Dual Hackathon Submissions:**
  - Projects may be cross-submitted to other hackathons running in the same calendar month, provided the other hackathon also permits dual submissions.
- [ ] **Originality & Anti-Plagiarism:**
  - All submitted code and hardware must be original work created during the hackathon period. Plagiarized code will result in immediate disqualification.

## 6. Official Judging Rubric (6 Evaluation Criteria)

The HackAlphaX judging committee evaluates each entry across 6 equally weighted criteria:

| # | Criterion | Evaluator Questions & Key Factors | Strategic Winning Approach |
| :-: | :--- | :--- | :--- |
| 1 | **Originality** | *Has this project been done before at hackathons in the past? How creative is the project in solving the problem at hand?* | Avoid generic carbon footprint calculators or simple to-do apps. Build an innovative angle (e.g., automated semantic reasoning, real-time edge telemetry, novel incentive model). |
| 2 | **Adherence to Track** | *Does the hack adhere to "Earth Forward"? Does it implement this theme fully or just partially?* | Deep, authentic integration into sustainability/climate. Not just green UI styling, but an actual mechanism solving an environmental bottleneck. |
| 3 | **Completion** | *Does the hack work? Did the team achieve everything they wanted?* | Zero mock buttons or broken workflows. Every flow shown in the video demo must be completely functional end-to-end. |
| 4 | **Learning** | *Did the team stretch themselves? Did they try to learn something new? What kind of projects have they worked on before?* | Clearly describe new tech stacks, APIs, algorithms, or hardware interfaces tackled for the first time during the event. |
| 5 | **Design (UI/UX)** | *Did the team put thought into the user experience? How well designed is the interface?* | Clean typography, intuitive user onboarding, responsive design, fast interactive feedback, polished visualizations. |
| 6 | **Technology ("Wow" Factor)** | *How technically impressive was the hack? Was the technical problem tackled difficult? Did it use a particularly clever technique or multi-component architecture?* | Sophisticated architecture combining data pipelines, semantic judgment models (TypeSafe Jev), real-world datasets, and real-time reactive UI. |
